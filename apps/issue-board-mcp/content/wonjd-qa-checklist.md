# CRM 신규계정 성장·유지 관리 기능 QA 체크리스트

## 1. QA 목적

본 체크리스트는 CRM 신규계정 성장·유지 관리 기능 개발 완료 후, 계약·재계약·일시정지·취급고·과거 계약정보 및 지표 산출 로직이 확정된 운영 기준에 맞게 동작하는지 검증하기 위한 것이다.

---

# 2. 계약 및 재계약 QA

## 2.1 다음 계약 등록

- [ ]  계약 유형과 기간을 입력하여 다음 계약을 등록할 수 있다.
- [ ]  계약 유형 또는 기간이 확정되지 않은 상태에서는 다음 계약 확정으로 처리되지 않는다.
- [ ]  다음 계약 등록일이 계약 확정일로 정상 저장된다.
- [ ]  실제 결제일과 관계없이 CRM 등록 시점을 기준으로 재계약 성공 여부가 판단된다.
- [ ]  실제 운영 시작일과 관계없이 CRM 등록 시점을 기준으로 재계약 성공 여부가 판단된다.
- [ ]  다음 계약의 계약기간이 기존 계약과 정상적으로 연결된다.

## 2.2 종료 예정일 이전 재계약

- [ ]  기존 계약 종료 예정일 이전에 다음 계약을 등록할 수 있다.
- [ ]  종료 예정일 이전에 다음 계약 등록 시 즉시 재계약 성공으로 판정된다.
- [ ]  기존 계약 종료 예정일까지 기다리지 않는다.
- [ ]  재계약 성공일이 다음 계약 등록일로 저장된다.
- [ ]  성공 확정 이후 기존 계약의 재계약 상태가 변경되지 않는다.
- [ ]  성공 확정된 건이 판정 대기 상태로 남지 않는다.

## 2.3 판정 대기

- [ ]  계약 종료 예정일이 지났으나 다음 계약이 없는 경우 판정 대기로 처리된다.
- [ ]  판정 대기 건은 재계약 성공으로 처리되지 않는다.
- [ ]  판정 대기 건은 재계약 실패로 처리되지 않는다.
- [ ]  판정 대기 건은 재계약률 분모에서 제외된다.
- [ ]  판정 대기 건수가 별도로 표시된다.
- [ ]  판정 대기 상태에서 다음 계약을 등록하면 성공으로 전환된다.
- [ ]  판정 대기 상태에서 종료 처리하면 실패로 전환된다.
- [ ]  결과 확정 시 해당 확정일의 월에 실적이 반영된다.

## 2.4 종료 및 실패

- [ ]  CRM에서 `종료` 처리하면 해당 계약의 최종 종료가 확정된다.
- [ ]  종료 처리와 동시에 재계약 실패로 판정된다.
- [ ]  종료 처리일이 실패 확정일로 저장된다.
- [ ]  실패 확정일이 속한 월에 실패 실적이 반영된다.
- [ ]  종료된 계약이 과거 성공 계약으로 잘못 집계되지 않는다.

---

# 3. 종료 후 재계약 QA

- [ ]  실패 확정된 계약을 `종료 → 시작`으로 되돌리는 방식으로 복구하지 않는다.
- [ ]  실패 확정된 기존 계약의 종료 이력이 유지된다.
- [ ]  기존 실패 기록이 과거 지표에서 유지된다.
- [ ]  동일 광고주가 다시 계약할 경우 새로운 계약을 등록할 수 있다.
- [ ]  새로운 계약에는 새로운 계약기간이 저장된다.
- [ ]  새로운 계약은 별도의 계약 회차로 관리된다.
- [ ]  새로운 계약 시작이 기존 실패 기록을 성공으로 변경하지 않는다.
- [ ]  기존 계약의 히스토리가 삭제되거나 덮어쓰기되지 않는다.
- [ ]  동일 광고주가 여러 차례 재계약·종료를 반복하더라도 계약 이력이 순서대로 보존된다.

---

# 4. 계약 유형 변경 QA

- [ ]  기존 계약기간 내에서 계약 유형만 변경할 수 있다.
- [ ]  계약 유형만 변경한 경우 재계약으로 집계되지 않는다.
- [ ]  계약기간을 새롭게 등록한 경우 다음 계약으로 인식된다.
- [ ]  계약 유형 변경과 신규 계약 등록이 정상적으로 구분된다.
- [ ]  유형 변경만으로 재계약 성공일이 생성되지 않는다.
- [ ]  신규 계약기간 등록 시에만 재계약 성공이 발생한다.

# 5. 일시정지 및 계약기간 QA

## 5.1 일시정지 등록

- [ ]  CRM에서 일시정지를 등록할 수 있다.
- [ ]  CRM에서 처리한 모든 일시정지가 계약기간 연장 대상으로 반영된다.
- [ ]  일시정지 시작일이 정상 저장된다.
- [ ]  재시작일이 정상 저장된다.
- [ ]  여러 차례 일시정지를 등록할 수 있다.
- [ ]  각 일시정지 기간이 개별적으로 보존된다.

## 5.2 일시정지 일수

- [ ]  8/1 일시정지 → 8/11 재시작 시 10일로 계산된다.
- [ ]  일시정지일은 연장 일수에 포함된다.
- [ ]  재시작일은 연장 일수에서 제외된다.
- [ ]  여러 일시정지 기간이 발생하면 각 기간이 합산된다.
- [ ]  중복되는 일시정지 기간이 중복 계산되지 않는다.
- [ ]  계약 종료일이 계산된 일수만큼 정확하게 연장된다.

## 5.3 종료 예정일 이후 운영

- [ ]  계약 종료 예정일 이후에도 운영상태가 `시작`이면 정상 운영 상태로 유지된다.
- [ ]  취급고가 계속 발생하는 경우 정상 운영일로 인정된다.
- [ ]  재계약 협의 중이라는 이유만으로 일시정지 처리되지 않는다.
- [ ]  해당 기간이 판정 대기 기간으로 관리된다.
- [ ]  이후 계약 등록 시 재계약 성공으로 확정된다.
- [ ]  이후 종료 처리 시 재계약 실패로 확정된다.
- [ ]  판정 대기 기간이 일시정지 기간에 포함되지 않는다.

---

# 6. 다음 계약기간 연장 QA

- [ ]  다음 계약이 이미 등록된 상태에서 현재 계약을 일시정지할 수 있다.
- [ ]  현재 계약의 종료일이 일시정지 일수만큼 연장된다.
- [ ]  다음 계약의 시작일도 동일한 일수만큼 연기된다.
- [ ]  다음 계약의 종료일도 동일한 일수만큼 연기된다.
- [ ]  현재 계약과 다음 계약의 기간이 불필요하게 겹치지 않는다.
- [ ]  일시정지가 여러 차례 발생해도 다음 계약기간에 동일하게 누적 반영된다.
- [ ]  계약기간 연장 시 기존 계약 이력이 훼손되지 않는다.

---

# 7. 계약 지표 QA

## 7.1 실적 반영월

- [ ]  계약 종료 예정일과 결과 확정일의 월이 다른 경우 결과 확정월에 반영된다.
- [ ]  7/31 종료 예정 → 8/3 성공 확정 시 8월 성공 실적으로 반영된다.
- [ ]  7/31 종료 예정 → 8/3 실패 확정 시 8월 실패 실적으로 반영된다.
- [ ]  판정 대기 상태에서는 확정 실적으로 집계되지 않는다.
- [ ]  결과 확정 후 해당 월의 지표가 정상적으로 갱신된다.
- [ ]  동일 계약이 여러 월의 성공/실패 실적에 중복 반영되지 않는다.

## 7.2 분모 처리

- [ ]  판정 대기 건은 재계약률 분모에서 제외된다.
- [ ]  성공 확정 건은 분모에 포함된다.
- [ ]  실패 확정 건은 분모에 포함된다.
- [ ]  성공·실패가 확정된 건의 분모가 정상적으로 증가한다.
- [ ]  판정 대기 → 성공 전환 시 해당 건이 분모에 추가된다.
- [ ]  판정 대기 → 실패 전환 시 해당 건이 분모에 추가된다.

# 8. 과거 계약정보 QA

## 8.1 입력 권한

- [ ]  관리자 계정으로 과거 계약정보를 입력할 수 있다.
- [ ]  영업담당자 계정으로 과거 계약정보를 입력할 수 있다.
- [ ]  권한이 없는 사용자는 과거 계약정보를 임의로 수정할 수 없다.
- [ ]  입력자 정보가 기록된다.

## 8.2 운영 마케터 및 소속팀

- [ ]  과거 계약의 운영 마케터를 입력할 수 있다.
- [ ]  당시 소속팀 정보를 입력할 수 있다.
- [ ]  영업담당자가 없어도 운영 마케터가 있으면 개인 지표에 반영된다.
- [ ]  운영 마케터가 확인되면 당시 소속팀 지표에도 반영된다.
- [ ]  영업담당자가 `원정대`로 되어 있어도 운영 마케터 기준 지표가 정상 산출된다.
- [ ]  운영 마케터를 확인할 수 없는 계약은 계정 전체 지표에 포함된다.
- [ ]  운영 마케터를 확인할 수 없는 계약은 개인 지표에서 제외된다.
- [ ]  운영 마케터를 확인할 수 없는 계약은 팀 지표에서 제외된다.

## 8.3 과거 매체 광고계정

- [ ]  과거 계약을 현재 연결된 매체 광고계정 기준으로 자동 생성하지 않는다.
- [ ]  과거 실제 운영한 매체 광고계정을 선택할 수 있다.
- [ ]  여러 매체 광고계정을 과거 계약에 연결할 수 있다.
- [ ]  당시 실제 운영하지 않은 광고계정이 지표에 잘못 포함되지 않는다.
- [ ]  과거 계약의 광고계정 연결정보가 저장된다.

# 9. 월 환산 취급고 QA

## 9.1 정상 운영일

- [ ]  조회한 월의 정상 운영일만 산정 대상에 포함된다.
- [ ]  일시정지일은 정상 운영일에서 제외된다.
- [ ]  종료 이후 기간은 정상 운영일에서 제외된다.
- [ ]  기타 기존 정상 운영일 제외 기준이 동일하게 적용된다.
- [ ]  여러 일시정지가 있는 경우 전체 일시정지 기간이 제외된다.

## 9.2 당일 데이터 제외

- [ ]  당일 취급고가 수집 중이면 당일 데이터를 산정에서 제외한다.
- [ ]  전일까지 확정된 데이터만 사용한다.
- [ ]  당일 데이터가 확정된 경우 정상적으로 산정 대상에 포함할 수 있다.
- [ ]  조회일에 따라 산정 대상 기간이 정확하게 변경된다.

## 9.3 평균 계산

예: 8/1~8/17 정상 운영, 취급고 합계 1,700만원

- [ ]  정상 운영일수 17일로 계산된다.
- [ ]  1,700만원 ÷ 17일 = 100만원으로 일평균이 계산된다.
- [ ]  일시정지 기간이 포함된 경우 해당 일수를 분모에서 제외한다.
- [ ]  일시정지 기간의 취급고가 합산되지 않는다.
- [ ]  월 환산 취급고가 정상적으로 계산된다.

# 10. 3일 연속 취급고 하락 QA

## 10.1 기본 조건

- [ ]  최근 정상 운영일 기준으로 취급고를 정렬한다.
- [ ]  당일 미확정 데이터는 제외한다.
- [ ]  일시정지 기간은 제외한다.
- [ ]  종료 기간은 제외한다.
- [ ]  정상 운영일이 아닌 날짜는 제외한다.

## 10.2 하락 판단

- [ ]  `100 → 80 → 60`이면 하락으로 표시된다.
- [ ]  `120 → 100 → 80 → 60`이면 하락 조건을 충족한다.
- [ ]  `100 → 80 → 90`이면 연속 하락으로 표시되지 않는다.
- [ ]  `100 → 100 → 80`이면 연속 하락으로 표시되지 않는다.
- [ ]  `100 → 80 → 60 → 40`이면 정상적으로 하락 상태가 유지된다.
- [ ]  중간에 일시정지가 있어도 정상 운영일만 이어서 비교한다.
- [ ]  당일 데이터가 미확정이면 전일까지의 데이터로 판단한다.

# 11. 직전 3개 정상 운영일 평균 0원 QA

- [ ]  직전 3개 정상 운영일 평균 취급고가 0원인지 확인한다.
- [ ]  평균이 0원이고 이후 취급고가 발생하면 `취급고 발생`으로 표시된다.
- [ ]  평균이 0원이고 이후에도 취급고가 0원이면 `변동 없음`으로 표시된다.
- [ ]  평균이 0원일 때 0으로 나누는 증감률 오류가 발생하지 않는다.
- [ ]  평균이 0원이 아닌 경우 기존 증감률 계산을 정상 적용한다.
- [ ]  `취급고 발생`과 `변동 없음`이 일반적인 `상승/하락` 상태와 구분된다.

# 12. 계약 이력 및 데이터 무결성 QA

- [ ]  계약을 신규 등록할 때 기존 계약 이력이 삭제되지 않는다.
- [ ]  종료 처리 후 기존 계약정보가 유지된다.
- [ ]  새로운 계약 등록 시 기존 계약의 종료일이 변경되지 않는다.
- [ ]  기존 실패 기록이 새로운 계약 등록으로 성공으로 변경되지 않는다.
- [ ]  계약 회차가 순서대로 관리된다.
- [ ]  각 계약의 시작일·종료일·상태가 서로 혼동되지 않는다.
- [ ]  계약기간 연장 시 변경 이력이 확인 가능하다.
- [ ]  일시정지 이력이 삭제되지 않는다.
- [ ]  여러 차례 계약·종료·재계약을 반복해도 전체 이력이 보존된다.

---

# 13. 지표 중복 집계 QA

- [ ]  동일 계약이 재계약 성공으로 중복 집계되지 않는다.
- [ ]  동일 계약이 성공과 실패 양쪽에 동시에 집계되지 않는다.
- [ ]  하나의 계약이 여러 월의 확정 실적에 중복 반영되지 않는다.
- [ ]  기존 실패 후 신규 계약이 발생해도 기존 실패 건은 유지된다.
- [ ]  신규 계약이 기존 계약의 실적을 덮어쓰지 않는다.
- [ ]  판정 대기 건이 확정 전 지표에 포함되지 않는다.
- [ ]  판정 대기 건이 확정 후 정확히 한 번만 지표에 반영된다.
