# CRM 신규계정 성장·유지 관리 지표 운영 기준

## 1. 개요 / 목적
> 🎯 **목적** — CRM 신규계정의 계약·운영 이력을 기준으로 성장·유지 지표를 일관되게 판정한다.

**플랫폼:** 웹

본 문서는 CRM 신규계정의 계약 및 운영 이력을 기반으로 성장·유지 관련 지표를 산출하기 위한 계약 판정, 운영기간, 취급고, 과거 데이터 관리 기준을 정의한다.

개발 착수 전에 운영 기준을 확정하고, 구현·QA·지표 산출 과정에서 아래 기준을 우선 적용한다.

## 2. 타깃 사용자 & 유스케이스

| 페르소나 | 니즈 | 핵심 유스케이스 |
| --- | --- | --- |
| 운영 마케터 | 운영 상태와 취급고 이상 신호를 정확히 본다 | 정상 운영일 기준 취급고, 3일 연속 하락, 0원 예외 상태 확인 |
| 영업담당자 | 계약 확정·연장·종료 이력을 정확히 입력한다 | 다음 계약 등록, 과거 계약 수기 입력, 광고계정 수기 연결 |
| 영업본부 관리자 | 담당자가 없는 계약도 기준에 맞게 관리한다 | 과거 계약 입력, 실패 이력 보존, 신규 계약 회차 관리 |
| 운영/지표 관리자 | 재계약·락인·실적 반영 월을 일관되게 계산한다 | 판정 대기 분모 제외, 확정월 반영, 개인/팀 귀속 관리 |

## 3. 핵심 운영 기준

| 우선순위 | 기준 | 확정안 | 근거 |
| --- | --- | --- | --- |
| 높음 | 1. 다음 계약 인정 시점 | 계약 유형과 기간이 확정되어 CRM에 등록된 시점 | 결제일/운영 시작일보다 실무 확정 시점이 지표 기준 |
| 높음 | 2. 종료 예정일 전 다음 계약 등록 | 등록 시점에 재계약 성공 확정 | 조기 연장 실무 반영 |
| 높음 | 3. 판정 대기 분모 처리 | 결과 확정 전까지 분모 제외, 대기 건수 별도 표시 | 지표 왜곡 방지 |
| 높음 | 4. 종료 처리 | 현재 종료를 최종 종료 및 재계약 실패로 사용 | 실패 확정 기준 단일화 |
| 높음 | 5. 실패 후 재계약 | 기존 실패 기록 유지, 이후 계약은 신규 계약으로 관리 | 히스토리 보존 |
| 높음 | 6. 일시정지 연장 대상 | CRM에서 처리한 모든 일시정지 기간 | 정상 운영기간만 계약기간으로 인정 |
| 높음 | 7. 일시정지 일수 계산 | 일시정지일 포함, 재시작일 제외 | 운영일 계산 기준 명확화 |
| 높음 | 8. 현재 계약 연장 시 다음 계약 연기 | 다음 계약 시작일·종료일도 동일 일수만큼 연기 | 계약기간 중첩 방지 |
| 높음 | 9. 계약 유형 변경 처리 | 다음 계약기간이 별도로 등록된 경우만 재계약 인정 | 단순 유형 변경과 갱신 구분 |
| 높음 | 10. 실적 반영 월 | 결과가 실제 확정된 월 | 종료 예정일이 아닌 확정일 기준 |
| 보통 | 11. 과거 계약 입력 권한 | 관리자와 영업담당자 모두 입력 가능 | 운영 가능성 확보 |
| 보통 | 12. 마케터/소속팀 미확인 계약 | 계정 전체 포함, 개인·팀은 제외 | 귀속 불명확 케이스 분리 |
| 보통 | 13. 과거 광고계정 연결 | 당시 실제 운영 광고계정을 수기 선택 | 과거 데이터 정합성 확보 |
| 높음 | 14. 월 환산 취급고 평균 기간 | 조회한 월의 정상 운영일, 당일 미확정 데이터 제외 | 운영 현실 반영 |
| 높음 | 15. 3일 연속 취급고 하락 | 최근 3개 정상 운영일이 연속 하락 | 이상 신호 탐지 기준 |
| 높음 | 16. 직전 3개 정상 운영일 평균 0원 | 증감률 대신 취급고 발생 / 변동 없음 | 0원 구간 예외 처리 |

## 4. 범위 밖 (Out of Scope)
> ⚠️ **범위 밖** — 이번 기준에 포함하지 않는 것들.

- 실제 결제일을 계약 확정 시점으로 사용하는 방식
- 실제 다음 계약 운영 시작일을 계약 확정 시점으로 사용하는 방식
- 종료된 기존 계약을 `종료 → 시작`으로 되돌려 과거 지표를 수정하는 방식
- 현재 연결된 매체 광고계정 기준으로 과거 계약을 일괄 생성하는 방식
- 당일 미확정 취급고 데이터를 평균·하락 판단에 포함하는 방식

## 7. 세부 확정 기준

### **1. 다음 계약 등록의 인정 시점**
계약 유형과 기간이 확정되어 CRM에 등록된 시점을 다음 계약의 인정 시점으로 본다.

- 실제 결제일을 기준으로 하지 않는다.
- 실제 운영 시작일을 기준으로 하지 않는다.
- 광고주와 계약 내용이 확정되어 CRM에 다음 계약정보가 등록된 시점을 계약 확정 시점으로 본다.

### **2. 종료 예정일 전에 다음 계약을 등록한 경우**
현재 계약 종료 예정일 전에 다음 계약이 등록되더라도, 다음 계약을 등록한 시점에 재계약 성공으로 확정한다.

- 기존 계약 종료 예정일까지 기다리지 않는다.
- 다음 계약의 유형과 기간이 확정되어 CRM에 등록된 날짜를 재계약 성공일로 본다.
- 조기 연장 계약도 동일 기준으로 처리한다.

### **3. 첫 재계약·락인 판정 대기 건의 분모 처리**
계약 종료 예정일이 지났더라도 다음 계약 등록 또는 실제 종료 처리가 없으면 성공/실패를 확정하지 않는다.

- 결과가 확정될 때까지 분모에서 제외한다.
- 판정 대기 건수로 별도 표시한다.
- 실제 종료 처리 시 실패로 확정한다.
- 다음 계약 등록 시 성공으로 확정한다.

### **4. 재계약 실패를 확정하는 종료 처리**
현재 CRM의 `종료` 처리를 최종 계약 종료 및 재계약 실패 확정으로 사용한다.

- 기존 계약의 종료/실패 이력은 그대로 유지한다.
- 종료 후 재대행이 발생하면 새로운 계약으로 등록한다.
- 새로운 계약의 운영 상태를 시작으로 재처리한다.
- 기존 계약을 `종료 → 시작`으로 되돌려 과거 지표를 변경하지 않는다.

### **5. 실패 확정 후 다시 계약한 경우**
기존 실패 기록은 유지하고 이후 계약은 새로운 계약으로 처리한다.

- 확정된 실패 데이터를 성공으로 되돌리지 않는다.
- 이후 계약은 새로운 계약 회차로 관리한다.
- 기존 누적 히스토리는 보존한다.

### **6. 계약기간 연장 대상 일시정지**
CRM에서 처리한 모든 일시정지 기간을 계약기간 연장 대상으로 본다.

- 제품 수급 문제, 광고계정 이슈, 장기 소진 어려움 등 CRM상 일시정지는 모두 포함한다.
- 종료 예정일 이후 재계약 협의 중 실제 운영을 계속하는 기간은 일시정지가 아니다.
- 해당 기간은 재계약 판정 대기이면서 정상 운영 중인 기간으로 본다.

### **7. 일시정지 일수 계산**
일시정지일 포함, 재시작일 제외 기준으로 일시정지 일수를 계산한다.

- 예: 8/1 일시정지, 8/11 재시작이면 10일이다.
- 재시작일은 정상 운영일로 포함한다.
- 일시정지가 여러 차례 발생하면 각 기간을 합산한다.

### **8. 다음 계약 등록 후 현재 계약기간이 연장된 경우**
현재 계약이 일시정지로 연장되면, 이미 등록된 다음 계약의 시작일과 종료일도 같은 기간만큼 연기한다.

- 현재 계약과 다음 계약이 겹치지 않도록 처리한다.
- 여러 차례 연장도 누적 반영한다.

### **9. 계약기간 중 계약 유형만 변경된 경우**
다음 계약기간이 별도로 등록된 경우에만 재계약으로 집계한다.

- 단순 계약 유형 값 변경만으로는 재계약으로 잡지 않는다.
- 실제 운영상 계약 유형 변경과 계약기간 재설정을 구분한다.

### **10. 계약 지표의 실적 반영 월**
파일럿 전환율, 첫 재계약률, 락인율 모두 결과가 실제 확정된 월을 기준으로 반영한다.

- 종료 예정일이 아니라 실제 성공/실패 확정일 기준이다.
- 예: 종료 예정일이 7/31이어도 실제 확정이 8/3이면 8월 실적으로 반영한다.
- 판정 대기 상태였던 계약도 확정 시점의 월에 반영한다.

### **11. 과거 계약정보 수기 입력 권한**
과거 계약정보는 관리자와 영업담당자 모두 입력할 수 있다.

- 해당 광고주의 영업담당자가 존재하면 영업담당자가 입력한다.
- 기존 담당자가 없거나 입력이 어려우면 영업본부 관리자가 입력한다.

### **12. 과거 담당자나 소속팀을 확인할 수 없는 계약**
개인/팀 기준은 운영 마케터를 우선 기준으로 한다.

- 영업담당자가 `원정대`여도 운영 마케터가 확인되면 개인·팀 지표에 포함한다.
- 운영 마케터와 당시 소속팀을 확인할 수 있으면 해당 개인·팀 지표에 반영한다.
- 예외적으로 운영 마케터까지 확인할 수 없으면 계정 전체 지표에는 포함하되 개인·팀 지표에서는 제외한다.

### **13. 과거 브랜드별 계약의 매체 광고계정 연결**
당시 실제 운영한 매체 광고계정을 확인해 수기로 선택한다.

- 현재 연결된 매체 기준으로 과거 계약을 일괄 생성하지 않는다.
- 당시 실제 운영 대상이었던 광고계정만 연결한다.

### **14. 월 환산 취급고의 평균 산정기간**
조회한 월의 정상 운영일을 기준으로 월 환산 취급고의 일평균을 계산한다.

- 당일 데이터가 수집 중이면 당일을 제외하고 전일까지의 확정 데이터만 사용한다.
- 일시정지 기간은 분모와 취급고 합산에서 모두 제외한다.
- 예: 8/18 조회 시 8/1~8/17 취급고 총액을 정상 운영일수로 나눈다.

### **15. 3일 연속 취급고 하락 기준**
최근 3개 정상 운영일의 취급고가 연속으로 낮아진 경우를 3일 연속 취급고 하락으로 본다.

- 예: `100 → 80 → 60`
- 당일 미확정 데이터는 제외한다.
- 분배, 일시정지, 종료 기간은 기존 기준과 동일하게 제외한다.

### **16. 직전 3개 정상 운영일 평균 취급고가 0원인 경우**
증감률 대신 최근 취급고가 발생하면 `취급고 발생`, 계속 0원이면 `변동 없음`으로 표시한다.

- 일반적인 증감률 계산과 별도 상태값으로 관리한다.
- 0으로 나누는 오류가 발생하지 않도록 한다.

### **파일럿·재계약·락인 지표 구분**
계약 지표는 최종적으로 아래 3단계로 구분하여 관리한다.

`파일럿 전환율 → 첫 재계약률 → 락인율`

- 파일럿 → 파트너/그로스 = 파일럿 전환
- 첫 유료계약 → 두 번째 유료계약 = 첫 재계약
- 첫 재계약 이후 추가 계약 유지 = 락인

각 지표의 성공/실패 실적 반영월은 10번 기준과 동일하게, 실제 결과가 확정된 월로 적용한다.

## 8. 개발 반영 시 우선 확인사항
> 📝 **가정/미결** — 현재 CRM 구조와 충돌하는 부분은 구현 전에 확인 후 협의한다.
